## 为什么要做 Web OS

最早只是想要一个干净的个人主页，放 Projects 和 Blog。但写着写着就变了味——我想让它像操作系统一样工作。

> “个人网站不应该只是一个展示柜，它应该是一个可以在浏览器里随时打开的工具。”

这句话在很多 Web OS 项目里都能看到。但真正做起来，我发现最难的不是「像 OS」，而是「稳定得像 OS」。

v0.8 之前的版本其实很松散。每次加新功能，样式就可能冲突；换个主题，布局就崩；换个语言，某些文案就消失。我意识到这不是功能问题，是**系统治理**的问题。

---

## 四个关键系统的搭建

v0.8 我做了四件事，看起来各自独立，其实是一个整体：

### 1. OS Design System

我把所有颜色、间距、圆角、阴影抽成 CSS 变量。最早是手写颜色，像 `#07120f`、`#a8c8bd` 这种硬编码散落在十几个文件里。后来用 preflight 脚本扫描，发现了 47 处。

现在只有两层：

- **Token 层**：语义化命名，如 `--surface-raised`、`--text-primary`、`--accent-text`
- **实现层**：具体组件引用 Token，不直接写颜色

这带来的改变是：主题切换只需要改 Token 的值，所有组件自动生效。

### 2. Motion System

Web OS 的核心体验在于「切换」。我在 v0.8.5 重写了整个 Motion System：

- Master–Detail 切换用 `translateX` 而不是 `opacity`，有物理感
- Detail 内容切换是 `opacity + scale`，平滑过渡
- Panel 进入动画：整个面板作为整体滑入，而不是内部元素各自动画

关键决策是**抑制冲突**。Detail Panel 滑入时，内部内容暂时不参与交换动画，等面板落定后再激活。这解决了之前 CSS transition 冲突导致的动画失效。

### 3. Article Composer

这是 v0.8 最意外的功能。我原本只想做一个「写博客」的页面，结果做成了一个富文本编辑器。

Composer 用的是本地 Markdown 编辑 + 实时预览，支持：

- 语法高亮
- 滚动同步
- 保存到本地存储

没有后端，没有数据库。文章写完导出 `.md` 文件，手动放到 `src/content/blog/` 目录。这种「手动提交」的方式反而让我更认真对待每一篇文章。

### 4. Settings 与主题 / i18n

Settings 页面是后来加的。最初只是想换个主题色，后来发现主题切换需要：

- CSS 变量替换
- 字体切换（正文用衬线，阅读模式用无衬线）
- 语言切换（目前支持中英文）
- 布局偏好（Master 宽度、Detail 位置）

我把 Settings 做成了一个独立的 App，和 Projects、Timeline、Composer 并列。这样用户在任意页面都可以随时打开设置，而不必跳转到专门页面。

## 为什么不再继续堆功能

v0.8.5 之后我停了一段时间，仔细想了一个问题：继续做新功能，还是先把现有的东西打磨稳？

我的选择是后者。原因有三个：

**第一，边界模糊。** 每加一个功能，都要和现有的系统竞争样式空间。Projects 的卡片样式和 Timeline 的时间轴样式原本就不同，硬要统一需要重写很多组件。

**第二，维护成本指数增长。** 6 个 App、3 种主题、2 种语言、几十篇博客，任何一处改动都可能触发连锁反应。没有 Design System Contract，根本不敢随便改。

**第三，用户感知有限。** 加一个新功能，用户可能三天后就忘了。但如果你把动画从 200ms 改成 300ms，或者把主题色从青色改成薄荷绿，用户立刻就能感觉到「变了」。

所以我把 v0.8.7 的精力放在了「统一治理」上：消除硬编码颜色、统一 Motion 时长、建 Design System Contract 文档。这些事不酷，但扎实。

## 数据与版本

v0.8 的开发过程中，我用了一些量化手段：

| 指标 | v0.8.0 | v0.8.7 | 变化 |
|------|--------|--------|------|
| 硬编码颜色数 | 47 | 0 | -100% |
| Motion 变体数 | 12 | 5 | -58% |
| Design System Token | 0 | 34 | 新增 |
| CSS 文件数 | 8 | 6 | -25% |

Token 数量从 0 到 34，是这次升级最实质性的变化。

## 接下来做什么

v0.8 稳定了，但还有一些没做完的事：

1. **移动端适配**：目前 Master–Detail 在手机上还是简单堆叠，没有真正的手势操作
2. **搜索功能**：博客和项目都没有全文搜索，Timeline 的筛选也很基础
3. **数据导出**：Composer 写的内容目前只能手动导出，希望有一键打包
4. **多语言扩展**：目前只有中英文，想加日文和西班牙文

但这些都要建立在「系统稳定」的基础上。v0.8 我花了很多时间填坑，v0.9 我希望能把坑变成路。

---

## 小结

v0.8 是一个从「做加法」到「做乘法」的版本。加功能是加法，搭系统是乘法。

Web OS 不只是一个酷的概念，它是一个需要持续维护的数字产品。当你把它当作产品而不是项目来对待时，很多决策就会变得不一样。

感谢每一个提交 Issue 和 PR 的人，也感谢那些只是「来看看」的朋友。这个项目最酷的地方在于：**它真的在浏览器里跑，而且不需要服务器**。
