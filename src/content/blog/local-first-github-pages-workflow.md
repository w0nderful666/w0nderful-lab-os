## 一个奇怪的选择

做个人网站这件事，大部分人的默认思路是：

1. 买一个域名
2. 租一个 VPS 或云服务器
3. 装 WordPress 或者自建后端
4. 配数据库、配置 HTTPS、配置备份

这个流程没有问题，很多成熟的方案。但我选择了一条完全不同的路：

- **没有后端**：所有逻辑都在浏览器里
- **没有数据库**：数据就是文件系统里的 Markdown 文件
- **没有登录系统**：不需要用户账号
- **部署方式是 GitHub Pages**：每次 `git push` 自动触发构建

很多人问我：这样不麻烦吗？我的回答是：**麻烦，但值得**。

---

## 零运维的真相

传统网站的运维成本可能被低估了。让我算一笔账：

| 维度 | 传统方案 (VPS + WordPress) | 我的方案 (GitHub Pages) |
|------|----------------------------|--------------------------|
| 服务器费用 | $5~20 / 月 | $0 |
| 域名费用 | ~$15 / 年 | ~$15 / 年 |
| 维护时间 | 每月安全更新、备份、监控 | 几乎为零 |
| 故障恢复 | 登录服务器排查 | 重新 `git push` |
| 扩展性 | 受限于服务器配置 | 受限于 GitHub 配额 |

更重要的是，我不需要担心：

- 服务器被打挂
- 数据库被 SQL 注入
- PHP / Node 版本不兼容
- SSH 密钥过期
- 磁盘空间不足

> 「最安全的系统是没有暴露在互联网上的系统。」

GitHub Pages 本身就是一道防火墙。我的站点不需要处理用户请求、不需要保存敏感数据、不需要 API 接口。它只是一个静态输出。

## 本地写的体验

Local First 的另一个核心是「本地编辑」。我写博客用的是 VS Code + 若干 Markdown 插件：

```markdown
---
title: "文章标题"
slug: "article-slug"
date: "2026-05-05"
---

## 正文

内容...
```

每一篇博客就是一个 `.md` 文件，保存在本地 `src/content/blog/` 目录。图片？直接放到 `public/` 目录，用相对路径引用。

这个工作流让我找回了写东西的「手感」。不需要登录后台，不需要等待页面加载，不需要担心编辑器崩溃丢失内容。文件就在那里，改完 commit，push，GitHub Actions 自动构建。

Workflow 大致是这样的：

1. **本地写**：VS Code 打开项目，编辑或新建 `*.md`
2. **本地测**：`npm run dev` 启动本地预览
3. **提交**：`git add . && git commit -m "add new post"`
4. **推送**：`git push origin pt`
5. **等待**：GitHub Actions 自动构建，2~3 分钟后生效

整个过程不需要浏览器介入，除了最后验证部署结果。

## 数据安全与备份

没有云数据库，备份怎么做？

答案是：**Git 本身就是备份。**

每次 commit 都是一个完整的时间点快照。GitHub 远程仓库是主备份，本地是副备份。即使我把本地文件全删了，只要 GitHub 上的仓库还在，随时可以 `git clone` 回来。

更极端的情况——GitHub 倒闭了怎么办？

我有本地备份。定期把仓库导出为 zip，存到 NAS 或移动硬盘。这不是自动化备份，但足够可靠。

> 过度依赖云同步的人，可能已经忘了「本地有一份」是什么感觉。

## 安全性考量

静态网站的攻击面极小。我总结了几个关键点：

**第一，没有动态输入。** 没有表单、没有搜索参数、没有用户提交内容。XSS、CSRF 这些 Web 漏洞在这个场景下几乎没有意义。

**第二，CDN 防护。** GitHub Pages 本身带 HTTPS，免费且自动续期。配合 Cloudflare 的 CDN（如果你用了自定义域名），可以过滤掉大部分恶意流量。

**第三，依赖隔离。** 项目用的 npm 包都是公开的，任何人都可以审查。没有任何私有依赖，也就不存在供应链攻击的风险。

**第四，最小暴露原则。** 我的站点没有 Analytics、没有第三方脚本、没有追踪像素。访客的隐私得到最大保护。

当然，这不是完美的安全方案。如果 GitHub 本身被攻击，或者有人通过社会工程拿到了我的仓库权限，情况会不同。但这个风险级别和其他普通站点是同一个量级，而不是「金融级」。

## 成本与可持续性

算一个长期账：

- 域名：$15 / 年
- 静态托管：$0
- 维护：几乎为零

五年总成本约 $75。如果用传统 VPS，五年大约 $300~1200，取决于配置。

> 这不是「省钱」，而是「合理」。

对于一个个人项目、一个博客、一个作品展示窗口，GitHub Pages 的性价比是无可争议的。

而且，随着时间推移，这个成本不会增加。VPS 会过期、需要续费、配置会过时。但 GitHub Pages 只要 GitHub 还在，就是永久免费。

---

## 我不推荐的场景

Local First 不是万能药。有几种情况我不建议用：

1. **需要用户注册、登录**：必须有后端，或者用 Firebase / Supabase 这种 BaaS
2. **需要实时数据**：股票行情、聊天应用、协作编辑
3. **需要支付功能**：Stripe 或微信支付需要后端配合
4. **流量巨大**：GitHub Pages 有配额限制，超出后会限速

但对于 **个人主页、博客、作品集、内部工具**，Local First 是完美的选择。

---

## 小结

Local First + GitHub Pages 对我而言不是一个技术选型，而是一个态度：

- 我不想被云服务商绑架
- 我想把数据放在自己手里
- 我想用一个「不高科技」的方式，做一个「高科技」的产品

w0nderful-lab-os 的每一次访问，都是一次零运维的静态文件请求。没有服务器进程，没有数据库连接，没有 API 调用。只有浏览器和 CDN 之间的 HTTP 往来。

这也许不是最「现代」的架构，但它是**最可持续**的架构之一。
